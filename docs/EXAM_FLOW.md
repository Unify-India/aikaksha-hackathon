# Abhyas Exam Architecture & Flow

This document outlines the end-to-end technical implementation of the Exam engine, verifying all major system paths from teacher creation to student submission and AI review gates.

## 1. Exam Creation & Initialization

- **Path:** `CreateExamPage` -> `ExamService.createExam()`
- **Implementation Details:**
  The UI strictly binds to the `IExam` interface. All critical parameters (`title`, `totalMarks`, `duration`, `subject`, `batchId`, `difficulty`, `status`, `date`, `startTime`, `endTime`) are collected.
  Crucially, the UI parses the literal date strings into **Unix Timestamps** (`startTimestampMs` and `endTimestampMs`) during save. This powers secure backend write protection.

## 2. Batch Assignment

- **Path:** `CreateExamPage`
- **Implementation Details:**
  The interface `IExam` strictly enforces an optional `batchId`. The Teacher's UI dropdown is populated securely via `BatchService.getBatches()`, preventing orphan exams and ensuring every exam is correctly linked to its respective student roster.

## 3. Teacher Dashboard & Exam List

- **Path:** `ExamListPage` (Teacher)
- **Implementation Details:**
  The list reads directly from `ExamService.getExams()` and `BatchService.getBatches()`. It maps `batchId` to human-readable batch names and cleanly filters exams by their exact state (`live`, `upcoming`, `past`, `draft`).

## 4. Student Discovery & Filtering

- **Path:** `ExamListPage` (Student)
- **Implementation Details:**
  When a student views their exams, the system:
  1. Resolves all `batchId`s the student is currently enrolled in via `users/student/${uid}/enrolledBatches`.
  2. Filters the global exam list, exclusively displaying exams that match their verified enrolled batches.

## 5. Exam Access Control (Anti-Cheat Time Locks)

- **Path:** `ExamGuidelinePage` & `ExamListPage` (Student)
- **Implementation Details:**
  Client-side time (`Date.now()`) is notoriously easily bypassed by students changing their device clock.
  **Solution:** We use Firebase RTDB's `/.info/serverTimeOffset` to accurately sync the true internet server time to the frontend.
  - The "Start Exam" button (in the list) and the "Begin Assessment" button (in guidelines) are strictly disabled unless `trueServerTime >= startTimestampMs` and `trueServerTime <= endTimestampMs`.

## 6. Secure Exam Submission Engine

- **Path:** `ExamViewPage` -> `exam_submissions/${examId}/${studentId}`
- **Structure Decision:** Submissions use a **flat architecture** (`exam_submissions`) rather than deep nesting (`batches/batchId/...`). This prevents massive performance bottlenecks associated with downloading entire batch trees just to read exam status.
- **Security Rule Enforcement (RTDB):**
  To prevent unauthorized submissions outside of the time window via API tampering, the Realtime Database is protected by the following rule logic:

  ```json
  "exam_submissions": {
    "$examId": {
      "$studentId": {
        // 1. Must be the logged-in student
        // 2. Must be actively enrolled in the batch tied to this exam
        // 3. Must submit BEFORE the exam time window expires!
        ".write": "auth.uid === $studentId && root.child('users/student/'+auth.uid+'/enrolledBatches/'+root.child('exams/'+$examId+'/batchId').val()).exists() && now <= root.child('exams/'+$examId+'/endTimestampMs').val()"
      }
    }
  }
  ```

  _(Note: The `now` variable in RTDB rules evaluates to the secure server time in milliseconds.)_

## 7. Review Gates & Multi-Channel Publishing (MCP & AI Copilot)

- **Pre-Publishing Review Gate (`ITeacherReviewGateAssignment`):**
  Questions generated by AI start in state `PENDING_REVIEW`. Before an exam or DPP is finalized, teachers or automated validator agents inspect each item:
  - Correctness of the answer key and options.
  - LaTeX equation syntax verification ($...$ and $$...$$).
  - Difficulty distribution balance across Bloom's taxonomy.
- **Post-Submission Student Grading Review (`GradingReviewService`):**
  For subjective exams or student grievance appeals, submissions enter a teacher evaluation queue.
- **Multi-Channel Distribution (`channels`):**
  Once approved, exams and practice questions can be broadcasted via `TELEGRAM`, `WHATSAPP`, or native `APP_OMR`.
